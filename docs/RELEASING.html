Release Process

This repository publishes PlcComm.Toyopuc. NuGet publishing is intentionally manual, but GitHub Releases must stay synchronized with the manually published NuGet version.

Required Artifacts

Every GitHub Release must include these three assets:

  • PlcComm.Toyopuc.<version>.nupkg
  • PlcComm.Toyopuc.<version>.snupkg
  • PlcComm.Toyopuc.<version>.dll.zip

The DLL zip should be built from the same commit as the release tag. Do not upload assets built from main when the release points at an older tag.

Version And Tag Rules

  • Use vX.Y.Z for new release tags.
  • Keep <Version> in src\Toyopuc\PlcComm.Toyopuc.csproj equal to the NuGet package version.
  • If older non-v tags exist, do not reuse the mixed style for new releases.
  • GitHub Release, NuGet package, and attached asset filenames must all refer to the same version.

Checklist

  1. Update the package version in src\Toyopuc\PlcComm.Toyopuc.csproj.

  2. Update CHANGELOG.md.

  3. Make sure DocFX is available for the documentation step:

    dotnet tool install -g docfx

  4. Run the release checks:

    .\release_check.bat

  5. Create and push the vX.Y.Z tag:

    git tag vX.Y.Z
git push origin vX.Y.Z

  6. Build release artifacts from the tag:

    git switch --detach vX.Y.Z
dotnet restore PlcComm.Toyopuc.sln
dotnet build PlcComm.Toyopuc.sln -c Release --no-restore
dotnet test PlcComm.Toyopuc.sln -c Release --no-build
dotnet pack src\Toyopuc\PlcComm.Toyopuc.csproj -c Release --no-build --output out
Compress-Archive -Path src\Toyopuc\bin\Release\net9.0\* -DestinationPath out\PlcComm.Toyopuc.X.Y.Z.dll.zip -Force
git switch main

  7. Publish the NuGet package manually.

  8. Create or update the GitHub Release for vX.Y.Z, then upload the .nupkg, .snupkg, and DLL zip assets.

  9. Mark the GitHub Release as Latest when it is the newest stable release.

Release Notes

Each GitHub Release should include:

  • Added APIs: list new public API names and the version they first appear in.
  • Compatibility: target framework, behavior changes, and migration notes.
  • Assets: list the attached .nupkg, .snupkg, and DLL zip filenames.

For Toyopuc, call out scan-control and address-format APIs explicitly when they are relevant, for example ReleaseScanStopAsync, RelayReleaseScanStopAsync, and ToyopucAddress.Format.

Use No new public API additions are called out for this release. when there are no public API additions.

Recommended Consumer Versions

When releases are coordinated across the PLC communication libraries, include a small recommended-version table in the release notes. Example:

Package Recommended version
PlcComm.Slmp 0.1.14
PlcComm.KvHostLink 0.1.11
PlcComm.Toyopuc 0.1.8

Verification

After publishing, verify the release:

gh release view vX.Y.Z --repo fa-yoshinobu/plc-comm-computerlink-dotnet --json tagName,name,assets,url
gh release list --repo fa-yoshinobu/plc-comm-computerlink-dotnet --limit 3

Confirm that:

  • the latest GitHub Release tag is vX.Y.Z;
  • exactly three release assets are present;
  • NuGet shows the same PlcComm.Toyopuc version;
  • release notes mention added APIs and compatibility.
